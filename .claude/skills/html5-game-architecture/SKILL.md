# HTML5 Game Architecture
Read `MASTER_DIRECTIVE.md` first. Design a clean JavaScript ES Module game using HTML, CSS, Canvas 2D and Vite. Separate lifecycle, runtime, domain/gameplay, rendering, input, UI, audio, persistence, platform adapters and content data. Define ownership, APIs, initialization/disposal and dependency direction. Avoid global mutable state, circular dependencies, monoliths and excessive micro-modules. Keep content declarative and versionable. Pin tooling dependencies; provide reproducible dev/build/test scripts. Use browser APIs behind narrow adapters where useful. Record material decisions as concise ADRs. Deliver module map, contracts and checks.
